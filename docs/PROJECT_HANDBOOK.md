# VORTEX — Cinematic Dark/Light Portfolio Theme — Project Handbook

**GitHub repository:** [vaishnavsawant1994-stack/vortex-Portfolio-](https://github.com/vaishnavsawant1994-stack/vortex-Portfolio-)  
**Documentation baseline:** 15 November 2026 · **Assessment type:** code structure, readme, manifests and available evidence—not a fresh production/CI/visual audit.

## 1. Product identity and objective
Motion-rich theme with cinematic scroll treatment, mouse effects, responsive layout and light/dark variants, presented using illustrative sample content.

**Who benefits:** Designers, creative developers and template customers.

## 2. Feature areas and user journeys
1. Dark and light portfolio presentation.
2. Cursor and scroll-reactive transitions.
3. Optional Netlify contact function.
4. Staging previews, screenshot QA and static assets.

A feature name may denote a documented requirement or source area; actual implemented, wired, and accepted status must be proven separately.

## 3. System architecture and repository map
Static HTML/CSS/JavaScript with `index.html`, `site.css`, `site.js`, `site-config.js`, `assets/`, `docs/`, `previews/`, `netlify/`. Multiple Python/JS quality scripts and release documents exist.

## 4. Current development and release status
README states V15 staging candidate, not a reference-perfect certified clone. AI-generated portrait/sample projects and disabled mail delivery until configured are explicit limitations.

**Evidence hierarchy:** observed source and exact-head tests > dated reports > roadmap statements. Live deployment and third-party operations must be independently verified.

## 5. Developer setup and validation
Run local Python HTTP server per README, inspect previews; use provided `test_v15.py`, `quick_perf.py`, JS/form checks and QA reports as applicable. Validate contact function only in configured test environment.

Read configuration carefully; use isolated data, staging credentials and approved migration plans. Presence of a command is not evidence it succeeded today.

## 6. Security, privacy, quality and risk
- Use rights-cleared imagery and independent design assets.
- Maintain legible contrast in both themes, reduced motion and mobile fallback.
- Do not publish demonstration contact claims as actual delivery.
Every future release should assess access control, input validation, failure modes, monitoring, retention, backup/restore, accessibility and rollback as applicable.

## 7. Next recommended milestones
1. Resolve remaining reference screenshot and cursor/motion gaps.
2. Qualify light/dark text and contrast at all viewports.
3. Test responsive behavior, email delivery and accessibility.
4. Record final verified deploy URL and release evidence.
